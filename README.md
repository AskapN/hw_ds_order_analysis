### Выполнив это задание, вы закрепите навык:

- Разрабатывать комплексный скрипт автоматизации с нуля;
- Организовывать чтение данных, их обработку и выгрузку результатов;
- Упаковывать логику в класс;
- Выполнять пакетную обработку нескольких файлов;
- Обеспечивать корректность и устойчивость решения.

### Инструменты и материалы, которые пригодятся для выполнения задания

- Лонгрид «Архитектура автоматизации» (основной материал)
- Python 3.8 или выше
- Библиотека: pandas (устанавливается через pip install pandas)
- Датасет: [Synthetic Order Records: 10K to 10M Records](https://www.kaggle.com/datasets/swainproject/synthetic-order-records-10k-to-10m-records) (лицензия CC BY 4.0, разрешено использование в учебных целях)

### Задание

Разработайте скрипт для пакетного анализа данных о заказах интернет-магазина. Данные находятся в нескольких CSV-файлах в папке data/. Скрипт должен обработать все файлы в папке, рассчитать метрики по каждому файлу и сохранить общий результат.

### Структура входных данных

Каждый CSV-файл содержит синтетические записи о заказах и имеет следующие поля:

| Поле | Описание | Тип | Пример |
|------|----------|-----|--------|
| order_id | Уникальный номер заказа | Целое число | 1, 2, 2003 |
| person_id | ID покупателя | Целое число | 1, 100, 5000 |
| order_date | Дата создания заказа | Строка (YYYY-MM-DD) | 2021-03-15 |
| status | Текущий статус заказа | Строка | Pending, Shipped, Delivered, Cancelled, Processing, Returned, On Hold |
| total_amount | Общая сумма заказа | Число с плавающей точкой | 24.99, 599.95 |
| currency | Код валюты | Строка | USD, EUR, GBP |
| payment_method | Способ оплаты | Строка | credit_card, paypal, klarna |
| shipping_method | Способ доставки | Строка | standard, express, fedex |
| notes | Примечания к заказу | Строка | заполнено примерно в 5% записей |

### Что должен делать скрипт:

- Находить все CSV-файлы в папке `data/` и обрабатывать их по очереди (пакетная обработка). Для тестирования достаточно взять файлы `order_10000.csv` и `order_100000.csv`.
- Для каждого файла читать данные, фильтровать только заказы со статусом «Доставлен» (`status == 'Delivered'`), рассчитывать три метрики: общую выручку (сумма `total_amount`), средний чек (среднее `total_amount`), количество заказов.
- Вся логика работы с данными (чтение, фильтрация, расчёты) должна быть упакована в класс, например `OrderAnalyzer`.
- Результат обработки всех файлов (название файла и рассчитанные метрики) сохранять в один CSV-файл в папку `reports/`.
- Скрипт должен быть устойчивым: если какой-то файл повреждён, пуст или имеет неверный формат, скрипт не должен падать. Такой файл нужно пропустить, записать сообщение об ошибке в лог-файл и продолжить обработку остальных файлов.
- При запуске скрипт должен выводить в консоль количество обработанных файлов и количество файлов с ошибками.

### Конечный результат работы - проект со следующей структурой:

```
order_analysis/
├── data/                  # сюда студент кладёт скачанные CSV-файлы
├── reports/               # сюда сохраняется результат
├── logs/                  # сюда сохраняется лог ошибок
├── src/
│   └── analyzer.py        # класс OrderAnalyzer
├── config.py
├── run.py
└── requirements.txt
```

Все файлы должны быть заполнены рабочим кодом. Скрипт должен запускаться командой python run.py и выдавать корректный результат.

### Инструкция к выполнению

1. Скачайте датасет с Kaggle. Вам понадобятся файлы `order_10000.csv` и `order_100000.csv`. Положите их в папку `data/`.
2. Создайте один испорченный файл (например, с неправильным количеством колонок или с нечисловыми значениями в колонке `total_amount`) — он понадобится для проверки устойчивости. Положите его в ту же папку `data/`.
3. Создайте структуру проекта, описанную выше.
4. В `requirements.txt` укажите `pandas`.
5. В `config.py` вынесите все настройки: пути к папкам, имя выходного файла, название колонки со статусом и значение статуса для фильтрации.
6. В `src/analyzer.py` создайте класс `OrderAnalyzer`. Класс должен содержать методы для загрузки файла (с обработкой ошибок), фильтрации доставленных заказов, расчёта метрик, обработки одного файла и обработки всех файлов в папке. При возникновении ошибок записывайте информацию в лог-файл в папке `logs/`.
7. В `run.py` создайте функцию `main`, которая загружает настройки, создаёт экземпляр класса `OrderAnalyzer`, вызывает метод обработки всех файлов и выводит результат в консоль. Не забудьте про конструкцию `if __name__ == "__main__"`.
8. Запустите скрипт и убедитесь, что корректные файлы обработаны, испорченный пропущен с записью в лог, а в папке `reports/` появился итоговый CSV-файл с метриками по каждому файлу.
9. Проверьте проект по чек-листу из раздела №6 лонгрида.

### Чек-лист самопроверки результатов

- Проект содержит папки `data/`, `reports/`, `logs/`, `src/` с файлом `analyzer.py`, а также файлы `config.py`, `run.py` и `requirements.txt`.
- Логика обработки данных упакована в класс `OrderAnalyzer`.
- Скрипт обрабатывает все CSV-файлы в папке `data/`, а не только один заданный.
- При возникновении ошибки в одном файле скрипт не останавливается — остальные файлы обрабатываются, а ошибка записывается в лог.
- В папке `logs/` появляется файл `errors.log` с информацией об ошибках (если ошибки были).
- Функция `main` в `run.py` короткая и содержит только создание экземпляра класса и вызов методов.
- Конструкция `if __name__ == "__main__"` присутствует.
- Скрипт запускается командой `python run.py` без ошибок.
- В папке `reports/` появляется файл `summary_report.csv` с корректными данными.

### Критерии оценки домашнего задания

**«Зачёт»**
·	Проект имеет правильную структуру;
·	Логика упакована в класс;
·	Скрипт обрабатывает все файлы в папке;
·	Скрипт устойчив к ошибкам (один плохой файл не ломает обработку остальных);
·	Ошибки логируются в файл в папке `logs/`;
·	Функция `main` чистая, есть защита `if __name__ == "__main__"`;
·	Скрипт работает без ошибок и создаёт корректный отчёт.

**«На доработку»**
·	Структура проекта нарушена (отсутствуют нужные папки или файлы);
·	Логика не в классе или класс используется формально;
·	Скрипт обрабатывает только один заданный файл;
·	Скрипт падает при ошибке в файле;
·	Нет логирования ошибок;
·	Бизнес-логика в main;
·	Отсутствует конструкция if **name** == "**main**";
·	Скрипт не запускается или выдаёт ошибки.

**«Незачёт»** ставится в крайнем случае, если вы присылаете пустое или недоработанное задание во второй раз после отправки работы на доработку.
